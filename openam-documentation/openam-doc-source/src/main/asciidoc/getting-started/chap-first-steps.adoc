== Get Started with OpenAM

ifdef::env-site[]
anchor:chap-first-steps[]
endif::[]

Start OpenAM and sign in to its administration console. Then use OpenIG to protect a page with an OpenAM access policy. This example uses HTTP on your own machine for evaluation. For deployment, see the xref:../install-guide/index.adoc[Installation Guide].

[#how-openam-helps-manage-access]
=== About OpenAM

OpenAM authenticates users and decides whether they can access resources. OpenIG enforces those decisions at the gateway before responding to requests for the protected page.

[#software-you-need]
=== Before You Start

Install https://docs.docker.com/get-started/get-docker/[Docker] and make sure the Docker daemon is running. The OpenIG exercise also uses https://docs.docker.com/compose/install/[Docker Compose]. Use a Bash terminal for the commands. Make sure host port 8080 is available for OpenAM and 8081 for OpenIG.

[#prepare-etc-hosts]
==== Configure Local Hostnames

Add both names to your hosts file. Edit `/etc/hosts` on Linux or macOS, or `C:\Windows\System32\drivers\etc\hosts` on Windows, with administrator privileges.

[source,text]
----
127.0.0.1 openam.example.test app.example.test
----

Use these names in the browser. OpenAM and OpenIG share the `example.test` cookie domain in this exercise.

[#install-openam]
=== Start and Configure OpenAM

anchor:software-setup[]
Create an isolated Docker network for the exercise and a named volume for OpenAM's configuration and embedded directory. Publish OpenAM on the loopback address.

[source,shell]
----
docker network create openam-quickstart
docker volume create openam-quickstart-data
docker run -d --name openam-quickstart --hostname openam.example.test \
  --network openam-quickstart --network-alias openam.example.test \
  --publish 127.0.0.1:8080:8080 \
  --mount type=volume,source=openam-quickstart-data,target=/usr/openam/config \
  openidentityplatform/openam:16.1.4
----

. Open http://openam.example.test:8080/openam/[the OpenAM configuration screen]. If the server is still starting, use `docker logs openam-quickstart` to check its progress.
. Choose *Create Default Configuration* and accept the license agreement.
. Set distinct passwords for the default OpenAM administrator (`amadmin`) and the default policy agent user. Generate new passwords for this exercise and keep them in a password manager.
. Select *Create Configuration*. After configuration succeeds, request the readiness endpoint from your host terminal.
+
[source,shell]
----
curl -fsS http://openam.example.test:8080/openam/isAlive.jsp | grep -F 'Server is ALIVE'
----
+
The endpoint should respond directly with HTTP 200 and include `Server is ALIVE`.
. Select *Proceed to Login* and sign in as `amadmin` with the administrator password you set. Verify that the console shows *Top Level Realm*.

[#protect-with-openig]
=== Protect a Page with OpenIG

Use the *Top Level Realm* in the OpenAM console for the following configuration.

[#create-quickstart-identities]
==== Create the User and Service Account

anchor:create-web-policy-agent-profile[]
. Go to *Subjects > User* and create two active users, `quickstart-user` for the browser and `quickstart-pep` for OpenIG. Use a different generated password for each user.
. Under *Subjects > Group*, create `quickstart-policy-evaluators`. On the group page, add `quickstart-pep` as its only member.
. Under *Privileges*, select the group and grant only *REST calls for policy evaluation*. This lets OpenIG request decisions for the signed-in user's session. Save the privilege changes.

[#configure-cookie-domain]
==== Share the Session Cookie and Allow the Return URL

. Go to *Configure > Global Services > Platform* and set the cookie domain to `.example.test`. Save the setting. OpenAM's default session cookie is named `iPlanetDirectoryPro`.
. Return to *Top Level Realm*. Under *Services*, add the *Validation Service* if it is missing. Add the exact URL `http://app.example.test:8081/protected` to *Valid goto URL Resources* and save. OpenAM can then return the browser to the protected page after login.

[#configure-policy]
==== Allow GET Requests to the Protected URL

. In *Top Level Realm*, go to *Authorization > Policy Sets > Default Policy Set > Add a Policy*.
. Name the policy `Quickstart protected page`. Select the `URL` resource type, choose the `*://*:*/*` pattern, replace it with `http://app.example.test:8081/protected`, and select *Add*. Create the policy.
. On the *Actions* tab, add *GET*, set it to *Allow*, and save your changes.
. On the *Subjects* tab, edit the default subject to use *Authenticated Users*. Confirm the selection and save your changes.

[#start-openig]
==== Start OpenIG

anchor:install-web-policy-agent[]
In a new working directory, create the subdirectory `routes`. Save the following as `routes/10-protected.json`.

[source,json]
----
{
  "condition": "${request.uri.path == '/protected'}",
  "handler": {
    "type": "Chain",
    "config": {
      "filters": [
        {
          "type": "SingleSignOnFilter",
          "config": {
            "openamUrl": "http://openam.example.test:8080/openam"
          }
        },
        {
          "type": "PolicyEnforcementFilter",
          "config": {
            "openamUrl": "http://openam.example.test:8080/openam",
            "pepUsername": "quickstart-pep",
            "pepPassword": "${env['OPENIG_PEP_PASSWORD']}",
            "ssoTokenSubject": "${contexts.ssoToken.value}"
          }
        }
      ],
      "handler": {
        "type": "StaticResponseHandler",
        "config": {
          "status": 200,
          "headers": {
            "Content-Type": ["text/plain; charset=utf-8"]
          },
          "entity": "Protected by OpenAM"
        }
      }
    }
  }
}
----

Save the following as `compose.yaml` in the working directory. OpenIG joins the Docker network created earlier and reaches OpenAM by its network alias.

[source,yaml]
----
services:
  openig:
    image: openidentityplatform/openig:6.2.0
    ports:
      - "127.0.0.1:8081:8080"
    environment:
      - OPENIG_PEP_PASSWORD
    volumes:
      - ./routes:/var/openig/config/routes:ro
    networks:
      - quickstart
    healthcheck:
      test: ["CMD", "curl", "--fail", "--silent", "--output", "/dev/null", "http://localhost:8080/protected"]
      interval: 5s
      start_period: 30s
networks:
  quickstart:
    external: true
    name: openam-quickstart
----

Enter the `quickstart-pep` password when prompted and wait for OpenIG to start.

[source,shell]
----
(
  IFS= read -rs -p 'Password for quickstart-pep: ' OPENIG_PEP_PASSWORD || exit
  printf '\n'
  export OPENIG_PEP_PASSWORD
  docker compose up --wait
)
----

[#try-it-out]
=== Verify the Redirect, Access, and Logout

. In your terminal, send an unauthenticated GET request to the protected URL. Expect HTTP 302 and a `Location` header pointing to OpenAM.
+
[source,shell]
----
curl -sS -D - -o /dev/null http://app.example.test:8081/protected
----
. Sign out of the administrator console. In a browser, open http://app.example.test:8081/protected[the protected page] and sign in as `quickstart-user`. OpenAM should return you to the protected page. Check for HTTP 200 in the browser's Network panel and the text `Protected by OpenAM`.
. While on the protected page and still signed in, run this request in the browser's developer console. Expect 403 because the policy grants only GET.
+
[source,javascript]
----
fetch('/protected', { method: 'POST' }).then(response => console.log(response.status))
----
. Open http://openam.example.test:8080/openam/[OpenAM] in the same browser and select *Log out* from the user menu. Open the protected page again. Expect another HTTP 302 to OpenAM and a sign-in prompt.

[#quickstart-cleanup]
=== Clean Up

Run `docker compose down` from the directory containing `compose.yaml` if you started OpenIG. Then remove the OpenAM container and the Docker network.

[source,shell]
----
docker stop openam-quickstart
docker rm openam-quickstart
docker network rm openam-quickstart
----

The named volume retains your OpenAM configuration and directory. To delete that data, run `docker volume rm openam-quickstart-data`. Remove the local hosts file entries when you finish.
