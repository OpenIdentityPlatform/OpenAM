[#how-to-run-openam-in-kubernetes]
== How To Run OpenAM in Kubernetes

[[how-to-run-openam-in-kubernetes-preface]]
=== Preface

This tutorial starts one OpenAM instance with embedded OpenDJ on Minikube for local evaluation. For production topology, storage, and availability decisions, see the xref:../deployment-planning/index.adoc[Deployment Planning Guide].

Install Minikube and `kubectl`. Start Minikube with four CPUs and 8 GB of memory for this example. The manifests use the `default` namespace and expect a default storage class.

[source,shell]
----
minikube start --cpus=4 --memory=8g
----

[[how-to-run-openam-in-kubernetes-create-openam-service]]
=== Create OpenAM Service

Create `openam-service.yaml` with a headless Service that provides a stable Pod DNS name during setup. The optional Ingress section creates a separate Service that routes only to ready Pods.

[source,yaml]
----
apiVersion: v1
kind: Service
metadata:
  name: openam
spec:
  clusterIP: None
  publishNotReadyAddresses: true
  ports:
    - port: 8080
  selector:
    app: openam
----

[source,shell]
----
kubectl --namespace default apply -f openam-service.yaml
----

[[how-to-run-openam-in-kubernetes-create-openam-statefulset]]
=== Create OpenAM StatefulSet

Create `openam-statefulset.yaml`. Use a published https://hub.docker.com/r/openidentityplatform/openam/tags[OpenAM image tag]. The example uses 16.1.4. Keep both OpenAM configuration properties pointed at the persistent volume mounted at `/usr/openam/config`.

[source,yaml]
----
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: openam
spec:
  serviceName: openam
  replicas: 1
  selector:
    matchLabels:
      app: openam
  template:
    metadata:
      labels:
        app: openam
    spec:
      securityContext:
        fsGroup: 0
      containers:
        - name: openam
          image: openidentityplatform/openam:16.1.4
          ports:
            - name: http
              containerPort: 8080
          env:
            - name: CATALINA_OPTS
              value: >-
                -Xmx2048m -server
                -Dcom.iplanet.services.configpath=/usr/openam/config
                -Dcom.sun.identity.configuration.directory=/usr/openam/config
          startupProbe:
            tcpSocket:
              port: http
            periodSeconds: 5
            failureThreshold: 60
          livenessProbe:
            tcpSocket:
              port: http
            periodSeconds: 10
          readinessProbe:
            exec:
              command:
                - sh
                - -ec
                - >-
                  status=$(curl --silent --show-error --max-time 3 --output /dev/null
                  --write-out '%{http_code}' http://127.0.0.1:8080/openam/isAlive.jsp)
                  && test "$status" = 200
            periodSeconds: 10
            timeoutSeconds: 5
          volumeMounts:
            - name: openam-data
              mountPath: /usr/openam/config
  volumeClaimTemplates:
    - metadata:
        name: openam-data
      spec:
        accessModes:
          - ReadWriteOnce
        resources:
          requests:
            storage: 5Gi
----

The startup and liveness probes check that Tomcat accepts connections. The readiness probe requires an HTTP 200 response from `isAlive.jsp` so a redirect to the installer keeps the Pod out of the optional Ingress backend pool. The readiness check covers the OpenAM configuration store check. Use separate service tests for authentication and token flows in a production deployment.

[source,shell]
----
kubectl --namespace default apply -f openam-statefulset.yaml
kubectl --namespace default get pods -l app=openam --watch
----

Wait for `openam-0` to be in the Running phase, then stop watching. A new instance reports `0/1` ready until you configure OpenAM. The volume must be writable by the image's `openam` user. If setup reports a permission error, check the provisioned volume's ownership and write permissions.

[[how-to-run-openam-in-kubernetes-openam-setup-and-configuration]]
=== OpenAM Setup and Configuration

On the machine running your browser, add the Pod's stable DNS name to your local hosts file.

----
127.0.0.1   openam-0.openam.default.svc.cluster.local
----

Forward the port directly to the running Pod so you can reach the installer before readiness succeeds.

[source,shell]
----
kubectl --namespace default port-forward pod/openam-0 8080:8080
----

Open http://openam-0.openam.default.svc.cluster.local:8080/openam/[the OpenAM configuration page]. Select *Create Default Configuration*, accept the license agreement, and enter unique passwords for the administrator and the policy agent identity. Select *Create Configuration*, then select *Proceed to Login* when setup finishes.

In another terminal, verify that the Pod becomes ready after setup.

[source,shell]
----
kubectl --namespace default rollout status statefulset/openam --timeout=5m
----

To verify that the volume persists the installation, restart the StatefulSet and wait for the replacement Pod to become ready.

[source,shell]
----
kubectl --namespace default rollout restart statefulset/openam
kubectl --namespace default rollout status statefulset/openam --timeout=5m
----

Start the Pod port-forward again and confirm that the browser opens the existing installation and you can sign in.

[[how-to-run-openam-in-kubernetes-add-external-access-via-ingress]]
=== Add External Access via Ingress

These optional steps demonstrate proxy access in the local evaluation cluster. Keep the HTTP example within your test network. For production, plan TLS termination, proxy trust, and the client-facing URL before deployment.

[[how-to-run-openam-in-kubernetes-preparation]]
==== Preparation

Use `openam.example.test` as the client-facing name. In the OpenAM console, create a site with `http://openam.example.test/openam` as the primary URL, set the existing OpenAM server's parent site, and add `openam.example.test` as a cookie domain for this test. See xref:../install-guide/chap-install-multiple.adoc#configure-sites[Configuring OpenAM Sites] for the site procedure.

[[how-to-run-openam-in-kubernetes-setup-ingress]]
==== Set Up Ingress

Install and configure an https://kubernetes.io/docs/concepts/services-networking/ingress/[Ingress controller] for your evaluation cluster. Run `kubectl get ingressclass` to find the class managed by that controller. Save the following as `openam-ingress.yaml` and replace `your-ingress-class` with its class name. The `/openam` path and its subpaths must reach OpenAM with their paths intact.

[source,yaml]
----
apiVersion: v1
kind: Service
metadata:
  name: openam-ready
spec:
  ports:
    - port: 8080
      targetPort: http
  selector:
    app: openam
---
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: openam-ingress
spec:
  ingressClassName: your-ingress-class
  rules:
    - host: openam.example.test
      http:
        paths:
          - path: /openam
            pathType: Prefix
            backend:
              service:
                name: openam-ready
                port:
                  number: 8080
----

[source,shell]
----
kubectl --namespace default apply -f openam-ingress.yaml
kubectl --namespace default get ingress openam-ingress
----

[[how-to-run-openam-in-kubernetes-test-access]]
==== Test Access

Use your Ingress controller's instructions to make its HTTP listener reachable from your workstation. Map `openam.example.test` to the listener's IP address on your workstation. Open http://openam.example.test/openam/[OpenAM through Ingress] and verify that sign-in, navigation, and logout stay on the expected public URL.
