== Removing OpenAM Software

ifdef::env-site[]
anchor:chap-uninstall[]
endif::[]

You can remove one node, reset an isolated lab instance, or retire the entire deployment. For removing policy agents, see the xref:../web-users-guide/chap-apache.adoc#uninstall-apache-agent[web agent guide] and the xref:../jee-users-guide/chap-apache-tomcat.adoc#uninstall-tomcat-agent[Java agent guide].

[#uninstall-OpenAM-core]
=== Removing One OpenAM Node

. Identify the instance's server URL, context path, and base installation directory. In the console, check Deployment > Servers > _Server Name_ > General > System. Record its configuration store, identity store, and CTS endpoints and suffixes.
. Remove the node from the load balancer and drain active requests. Back up its local configuration directory and keys, record any settings needed for rollback, and secure the backup. See xref:../upgrade-guide/chap-about-upgrades.adoc#pre-upgrade-backup[backup guidance].
. If the node runs a replicated embedded OpenDJ instance, confirm that an up-to-date copy exists on the remaining nodes. Remove the retiring directory replica from the replication topology before shutting it down. See link:https://doc.openidentityplatform.org/opendj/admin-guide/chap-replication#stop-repl-permanent[Stopping Replication Permanently].
. Stop the OpenAM application. If you use Tomcat dedicated to this node, stop the Tomcat service. In a shared container, undeploy only the intended application. Remove the instance's WAR, expanded web application, and any context descriptor that would redeploy the WAR. For Docker, stop and remove the matching container. Keep its volume until the retirement is confirmed.
. If retiring the node from a site, remove its registered server URL from a remaining server in the site. See xref:../reference/openam-cli-tools.adoc#ssoadm-delete-server[`ssoadm delete-server`]. Verify that the remaining nodes serve requests.
. Once the removal is confirmed, remove the instance's local configuration directory and its bootstrap locator file, if any. The locator is an individual file named `AMConfig<normalized-webapp-path>` under the container service account's `$HOME/.openamcfg/` or legacy `$HOME/.openssocfg/`. For example, an expanded Tomcat app at `/path/to/tomcat/webapps/openam/` can use `$HOME/.openamcfg/AMConfig_path_to_tomcat_webapps_openam_`. Inspect the locator and confirm it points to the recorded base directory before deleting it. A preset configuration directory can eliminate the locator. Leave sibling locator files in place.
+
Removing the local configuration directory or its Docker volume also removes its embedded OpenDJ data and keystores. Keep shared configuration, CTS and identity services intact when retiring a single node.

[#reset-evaluation-installation]
=== Resetting a Disposable Evaluation Instance

This procedure applies to an isolated instance that uses disposable embedded stores. Its local realms, identities, tokens and keys are discarded.

. Stop the web application or container.
. Move the verified local configuration directory and only its matching bootstrap locator file out of the way. With Docker, recreate the container with a new, empty volume mounted at `/usr/openam/config`. Keep the original files or volume until you confirm the reset.
. Start OpenAM with the same WAR or image and open the setup URL. Complete xref:chap-install-core.adoc#configure-openam-defaults[evaluation setup] again.
. After verifying the new installation, dispose of the old lab files or volume securely.

[#purge-openam-deployment]
=== Retiring an Entire Deployment

. Inventory dependent agents, applications, OAuth and federation integrations, and any shared directory or CTS data. Schedule the cutover and confirm the retention policy for each data store.
. Back up each node's local configuration and keys and export or back up the external OpenAM data. Confirm the backups can be restored. Remove all OpenAM nodes using xref:#uninstall-OpenAM-core[the node removal procedure].
. Ask the directory owner to remove only the external data dedicated to the retired deployment, after confirming that no remaining node or application uses it. Use the deployed suffix from installation settings or the bootstrap configuration. The current default for OpenAM configuration is `dc=openam,dc=openidentityplatform,dc=org`. External stores and older installations may use a different DN. Directory servers, shared LDAP entries, user data, shared CTS data, and shared indexes or schema can serve other applications and should be preserved.
