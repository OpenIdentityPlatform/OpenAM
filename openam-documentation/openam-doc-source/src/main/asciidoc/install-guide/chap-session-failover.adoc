== Setting Up OpenAM Session Failover

ifdef::env-site[]
anchor:chap-session-failover[]
endif::[]

OpenAM 16.x persists established stateful sessions in the Core Token Service (CTS). A serving node can read a valid session from CTS when it is absent from its local cache. Session continuity requires both a load balancing layer that can route around failed nodes and a CTS store that remains accessible to the surviving nodes.

An authentication exchange can have node-local state before OpenAM establishes the session. If the node fails during that exchange, a user may have to start the flow again. Test affinity for multi-request authentication separately from failover of an established session.

OpenAM stores stateless session data in a client-held JWT. A surviving server can accept the token when it has compatible settings and cryptographic material. When stateless-session revocation is enabled, its denylist uses CTS. See xref:../admin-guide/chap-session-state.adoc#chap-session-state[Configuring Session State].

For stateful session continuity across sites, configure the sites in one OpenAM deployment with consistent naming configuration. Every site must recognize the original server and site IDs carried in the session and be able to read the session record from the same logical CTS. If replication lags, a recently issued, modified, or revoked session may have a different state at the surviving site. Measure replication lag, DNS and traffic redirection time, and user-visible results during failover and failback.

[#enable-session-failover]
=== Prepare an OpenAM Site for Session Failover

. xref:chap-install-multiple.adoc#configure-sites[Configure a site] and add multiple OpenAM servers behind its load balancer. For cross-site failover, add all participating sites to the same deployment.
. xref:chap-cts.adoc#chap-cts[Configure the CTS] so that all servers serving the same stateful sessions can read and write the same logical token store. Check store reachability and replication before admitting traffic.
. xref:chap-install-multiple.adoc#configure-lb[Configure load balancing]. Validate the public URL, any authentication affinity rules, and routing around unavailable nodes.
. Test session continuity through the site URL before releasing the site.

[#verify-session-failover]
=== Test Session Failover

. In a staging environment, establish a session through the site URL with a test user and identify the OpenAM node serving the session.
. Remove that node from service. Keep the same site URL and client session. Issue a new request that requires authentication and verify that the expected surviving node accepts the session.
. Check the behavior of logout and subsequent access across the nodes according to your revocation settings. Separately interrupt a multi-step login to verify how clients recover before a session is established.
. Test loss of a CTS replica. For multi-site deployments, also test site redirection and failback. Record the time until requests succeed again and whether any test session requires reauthentication.
. Restore the original routing and confirm normal operation.
