[#deploy-openam]
.To Deploy OpenAM
====
Select the WAR from xref:chap-prepare-install.adoc#download-openam-software[Obtaining OpenAM Software]. Use a non-root context and keep the same context at the proxy, if you have one. This example installs the combined WAR as `/openam` on Tomcat.

. Stop Tomcat, then copy the WAR into its configured application directory. The WAR filename sets the default Tomcat context path.
+
[source, console, subs="attributes"]
----
$ cp OpenAM-{openam-version}.war /path/to/tomcat/webapps/openam.war
----
+
Use the xref:../upgrade-guide/chap-upgrade-servers.adoc#upgrade-server[upgrade procedure] to replace a WAR in an existing installation.

. Start Tomcat and check the container log for deployment errors. On first boot, the application opens its setup screen. Restrict access to the setup interface to the installation operator until configuration is complete.
+
Open the intended URL, for example `https://openam.example.com:8443/openam` for Tomcat with HTTPS enabled. Configure the instance with xref:#configure-openam-custom[the custom wizard] or xref:chap-install-tools.adoc#install-openam-config-tools[the configurator CLI].
+

image::images/openam-start.png[]

[#install-openam-docker]
=== Running the OpenAM Docker Image

The image includes Tomcat, Java, the combined WAR at `/openam`, and both tool bundles already unpacked under `/usr/openam`. Pin the image to the release you plan to run. This evaluation example publishes the HTTP port only on the local machine.

[source, console]
----
$ docker volume create openam-config
$ docker run -d --name openam -p 127.0.0.1:8080:8080 \
    -v openam-config:/usr/openam/config \
    openidentityplatform/openam:16.1.4
----

Map `openam.example.com` to `127.0.0.1` for this example and open `http://openam.example.com:8080/openam` to configure OpenAM. Use `/usr/openam/config` as the configuration directory. For production, use the intended HTTPS hostname and keep the backend access private.

Keep `/usr/openam/config` on persistent storage to preserve local configuration, keys, and any embedded directory data when the container is replaced. The image runs as UID `1001`. If you use a bind mount, give that UID write access to the host directory. Use a distinct configuration volume for each OpenAM node and mount the same volume when replacing a node.

[#verify-openam-installation]
=== Verifying the Installation

After setup, query each node directly using its configured host, port, and deployment path. For example, for Tomcat with HTTPS enabled, run the following command.

[source, console]
----
$ curl --silent --show-error --include https://openam.example.com:8443/openam/isAlive.jsp
----

Expect HTTP `200` and `Server is ALIVE` in the response body. Check both with redirects disabled. An unconfigured instance can redirect to setup with HTTP `302`, and following that redirect can yield a setup page with HTTP `200`. Use this direct check for readiness even if the image's health check follows redirects.

Open the configured login URL in a browser, sign in as `amadmin`, and confirm that you can access the administration console. If you configured an external user store, sign in as a test user from that store as well. For a site, repeat the browser check at the load balancer URL before admitting traffic.

[#configure-openam-defaults]
.To Configure OpenAM With Defaults
====
Use default configuration for evaluation. The wizard provisions embedded OpenDJ as the configuration and identity stores. It uses the default directory ports when available and selects free ports when they are occupied.

The default configuration sets the cookie domain based on the full URL that was used to access the configurator, such as `example.com`, `server.west.example.com`, or `example.local`.

Configuration settings are saved to the home directory of the user running the web application container in a directory named after the deployment URI. For example, the default directory for `/openam` is `$HOME/openam` on a WAR installation. The Docker image sets a different path.

. In the initial configuration screen, click Create Default Configuration under Default Configuration.

. Review the software license agreement. If you agree to the license, click "I accept the license agreement", and then click Continue.
+

[#figure-openam-license]
image::images/openam-license-dialog.png[]

. Provide different passwords for the default OpenAM administrator, `amadmin`, and default Policy Agent users.
+

[#figure-openam-default-conf]
image::images/openam-default-conf.png[]

. When the configuration completes, click Proceed to Login, then sign in as the OpenAM administrator with the first of the two passwords you provided.
+

[#figure-openam-first-login]
image::images/openam-first-login.png[]
+
After successful login, OpenAM redirects you to OpenAM Realms.
+

[#figure-openam-console-first-time]
image::images/openam-realms.png[]

[#configure-openam-custom]
.To Custom Configure OpenAM
====

. In the initial configuration screen, click Create New Configuration under Custom Configuration.

. Read the license agreement. If you agree to the license, click "I agree to the license agreement", and then click Continue.

. On the Default User Password page, provide a password with at least eight characters for the OpenAM Administrator, `amadmin`.
+

[#figure-openam-conf-amadmin]
image::images/openam-conf-amadmin.png[]

. Verify that the server settings are valid for your configuration.
+

[#figure-openam-conf-server-settings]
image::images/openam-conf-server-settings.png[]
+
--

Server URL::
Provide a valid URL to the base of your OpenAM web container, including a FQDN.
+
In a test environment, you can simulate the FQDN by adding it to your `/etc/hosts` as an alias. The following excerpt shows lines from the `/etc/hosts` file on a Linux system where OpenAM is installed.
+

[source]
----
127.0.0.1 localhost.localdomain localhost
::1 localhost6.localdomain6 localhost6
127.0.1.1 openam openam.example.com
----

Cookie Domain::
Domain that created cookies will be valid for, for example `example.com`.

Platform Locale::
Supported locales include en_US (English), de (German), es (Spanish), fr (French), ja (Japanese), ko (Korean), zh_CN (Simplified Chinese), and zh_TW (Traditional Chinese).

Configuration Directory::
Location on server for OpenAM configuration files. OpenAM must be able to write to this directory.

--

. In the Configuration Store screen, select the prepared external OpenDJ store and enter its endpoint, LDAPS port, root suffix, and bind credentials. For a single-node evaluation, the wizard can provision an embedded directory.
+
[#figure-openam-conf-store]
image::images/openam-conf-store.png[]
+
Provision the external backend before running the wizard. The installer can add a missing base entry to an existing backend when the account has permission. See xref:chap-prepare-install.adoc#install-prepare-opendj-external-config-store[Preparing an External OpenDJ Configuration Store]. To join a deployment, see xref:#add-servers-to-site[Adding a Server to a Site].

. In the User Store screen, you configure where OpenAM looks for user identities.
+
Prepare the directory schema and assign the bind account the privileges needed for your user management features. See xref:chap-prepare-install.adoc#prepare-identity-repository[Preparing an External Identity Repository].
+

[#figure-openam-conf-user-store]
image::images/openam-conf-user-store.png[]
+
--

User Data Store Type::
If you have already provisioned a directory service with users in a supported user data store, then select that type of directory from the options available.

SSL/TLS Enabled::
Select this option for LDAPS. Configure the directory's LDAPS listener and trust its issuing CA in the JVM running OpenAM. The wizard uses direct TLS for this option.

Directory Name::
FQDN for the host housing the directory service.

Port::
Use the port on the directory's LDAPS listener, for example `1636`.

Root Suffix::
Base distinguished name (DN) where user data is stored.

Login ID::
DN of the temporary identity store setup account with permission to load schema, entries, ACIs, and indexes. After setup, switch the realm data store to the scoped runtime account. See xref:chap-prepare-install.adoc#prepare-idrepo-datastore[Configuring OpenAM Data Stores].

Password::
Password for the OpenAM bind account.

--

. In the Site Configuration screen, set up OpenAM as part of a site if it will be behind a load balancer. Enter the site name and the URL clients use to reach OpenAM through the load balancer.
+
[#figure-openam-conf-site]
image::images/openam-conf-site.png[OpenAM Site Configuration screen with site name and load balancer URL fields]
+
You can also xref:chap-install-multiple.adoc#configure-site-after-installation[configure a site after installation]. OpenAM persists established stateful sessions in CTS. If the site has multiple servers, xref:chap-session-failover.adoc#chap-session-failover[configure and test session failover] using a CTS that is accessible to the surviving servers.

. In the Agent Information screen, provide a password with at least eight characters to be used by policy agents to connect to OpenAM.
+

[#figure-openam-conf-pa]
image::images/openam-conf-pa.png[]

. Check the summary screen, and if necessary, click Previous to return to earlier screens to fix any configuration errors as needed.
+

[#figure-openam-conf-summary]
image::images/openam-conf-summary.png[]
+
After you click Create Configuration in the summary screen, configuration proceeds, logging progress that you can read in your browser and later, in the installation log. The process ends, and OpenAM shows the Proceed to Login prompt.
+

[#figure-openam-proceed-to-login]
image::images/openam-proceed-to-login.png[]

. When the configuration completes, click Proceed to Login, then sign in as the OpenAM administrator, `amadmin`.
+

[#figure-openam-first-login-admin]
image::images/openam-first-login.png[]
+
After login, OpenAM redirects you to the OpenAM Realms page.
+

[#figure-openam-console]
image::images/openam-realms.png[]
+
You can also access the combined WAR's console at `https://openam.example.com:8443/openam/console/`.

. Restrict permissions to the configuration directory (by default, `$HOME/openam`, where $HOME corresponds to the user who runs the web container). Give the container service account access and protect local bootstrap files and keys from other users.

. If your external identity repository stores federation attributes, prepare the required indexes. See xref:chap-prepare-install.adoc#install-index-opendj-external-idrepo["To Index External Identity Repository Attributes"] for more information.

[#add-servers-to-site]
.To Add a Server to a Site
====
High availability requires redundant servers in case of failure. With OpenAM, you configure an OpenAM site with multiple servers in a pool behind a load balancing service that exposes a single URL as an entry point to the site.

Follow these steps to configure a server to an existing site.

. In the initial configuration screen, under Custom Configuration, click Create New Configuration.

. In the first screen, enter the same password entered for the OpenAM Administrator, `amadmin`, when you configured the first server in the site.

. Configure server settings as required.
+
The cookie domain should be identical to that of the first server in the site.

. In the configuration store screen, select Add to Existing Deployment, and enter the URL of the first OpenAM server in the site.
+
Use the same shared configuration directory service as the other OpenAM servers. Prepare replication and directory failover on the external OpenDJ service before adding production nodes.
+
Settings for the user store are then shared with the existing server, so the corresponding wizard screen is skipped.

. In the site configuration screen, select `Yes` and enter the same site configuration details as for the first server in the site.
+
Settings for agent information are also shared with the existing server, so the corresponding wizard screen is skipped.

. In the summary screen, verify the settings you chose, and then click Create Configuration.

. When the configuration process finishes, click Proceed to Login, then sign in as the OpenAM administrator to access OpenAM Console.

[#troubleshoot-openam-installation]
.To Troubleshoot an OpenAM Installation
====
OpenAM can capture information in debug log files that are useful when troubleshooting OpenAM problems. xref:../admin-guide/chap-monitoring.adoc#debug-logging["Debug Logging"] in the __Administration Guide__ describes how to enable debug logging after OpenAM has been started.

It is also possible to capture debug logs while installing OpenAM. This can be useful if you need to troubleshoot an installation problem.

Follow these steps to capture debug logs while installing OpenAM on Tomcat:

. If Tomcat is already started, stop it.

. Append the debug option to the existing `CATALINA_OPTS` in Tomcat's `setenv.sh`. Keep the heap settings and module exports from xref:chap-prepare-install.adoc#prepare-java[Preparing a Java Environment].
+
[source, shell]
----
export CATALINA_OPTS="$CATALINA_OPTS -Dcom.iplanet.services.debug.level=message"
----

. Run the OpenAM installation. Debug log files containing troubleshooting information appear in the `debug` subdirectory of the configured OpenAM base directory.

. When you have completed OpenAM installation and no longer need to capture debug logs, stop Tomcat, revert the debug logging options, and restart Tomcat.
