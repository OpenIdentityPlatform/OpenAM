== Installing OpenAM Tools

ifdef::env-site[]
anchor:chap-install-tools[]
endif::[]

Download the tool ZIPs for the same version as OpenAM, either as xref:chap-prepare-install.adoc#download-openam-software[separate release assets or from the full kit]. Extract each archive into its own directory. The commands below use standalone downloads in `$HOME/Downloads`. Set `JAVA_HOME` to a supported JDK before running them.

[#install-openam-admin-tools]
=== Installing the Administration Tools

If the endpoints use private CAs, configure the JVM used by setup and by `ssoadm` to trust the issuing CA for each connection it makes. HTTPS to OpenAM and LDAPS to its configuration directory can have different issuers. For example, set `JDK_JAVA_OPTIONS` for this tools session with the path to a certificates-only JKS trust store containing the relevant CA certificates.

[source, shell]
----
export JDK_JAVA_OPTIONS="${JDK_JAVA_OPTIONS:+$JDK_JAVA_OPTIONS }-Djavax.net.ssl.trustStoreType=JKS -Djavax.net.ssl.trustStore=/secure/openam-tools-truststore.jks"
----

The server JVM also needs its own trust configuration for the directory connections it makes.

. Verify the server has completed setup and is xref:chap-install-core.adoc#verify-openam-installation[ready]. Run setup on a host that can read the server's local bootstrap configuration and reach the relevant directory and OpenAM endpoints.
+
[source, console, subs="attributes+"]
----
$ mkdir -p "$HOME/openam-tools/admin"
$ cd "$HOME/openam-tools/admin"
$ unzip "$HOME/Downloads/SSOAdminTools-{openam-version}.zip"
$ ./setup
----
+
On Windows, run `setup.bat`. To accept the license noninteractively after reviewing it, use `./setup --acceptLicense` or `setup.bat --acceptLicense`. Specify the OpenAM base configuration directory, which contains the bootstrap data, and writable locations for the tools' logs and debug files. For a typical WAR installation at `/openam`, the base directory is `$HOME/openam` under the container service account's home.
+
Setup generates `ssoadm`, `ampassword`, and `amverifyarchive` in a directory named for the deployed instance, for example `openam/bin`. The generated Windows scripts use the `.bat` extension.

. For a site deployment, set the generated `ssoadm` script's `com.iplanet.am.naming.map.site.to.server` Java system property before the main class invocation, on a single line. Map the site URL to the specific server whose configuration you used for this setup.
+
[source, shell]
----
-D"com.iplanet.am.naming.map.site.to.server=https://lb.example.com/openam=https://openam.example.com:8443/openam"
----

. Create a password file readable only by the operator, containing the OpenAM administrator password on a single line. Use a secure editor or a secret mounted by your secret manager. Pass the file to `ssoadm` and remove a temporary copy when finished.
+
[source, console]
----
$ chmod 400 /secure/openam-admin.pwd
$ ./openam/bin/ssoadm list-servers -u amadmin -f /secure/openam-admin.pwd
----
+
Confirm that the result lists the expected server or site members. For the optional browser interface, see xref:../admin-guide/chap-admin-tools.adoc#openam-ssoadm-jsp-overview[OpenAM ssoadm.jsp].

[#install-openam-config-tools]
=== Configuring OpenAM with the CLI

Use the configurator on a deployed and running instance that is still on its first-boot setup screen. The command sends the properties to the server's configurator over HTTP or HTTPS. `BASE_DIR` is a path on the server, and it must be writable by the web container service account.

[source, console, subs="attributes+"]
----
$ mkdir -p "$HOME/openam-tools/config"
$ cd "$HOME/openam-tools/config"
$ unzip "$HOME/Downloads/SSOConfiguratorTools-{openam-version}.zip"
$ umask 077
$ cp sampleconfiguration config.properties
$ chmod 600 config.properties
----

Edit `config.properties` in a private directory and replace the sample secrets before use. For the project Docker image, set `BASE_DIR=/usr/openam/config` to use its persistent configuration mount. `SERVER_URL` is the scheme, host, and port of the web endpoint. Set `DEPLOYMENT_URI` separately, for example `/openam`. Set a unique administrator password and a distinct default agent password, then set `ACCEPT_LICENSES=true` once you have reviewed and accepted the license. Leave `AM_ENC_KEY` blank to generate a key for a standalone installation.

For an embedded evaluation instance, use `DATA_STORE=embedded` and the embedded directory settings and ports in `sampleconfiguration`. Set `DIRECTORY_SERVER` to the directory host and ensure its chosen ports are free. `DIRECTORY_SSL=SIMPLE` in an embedded example describes the directory connection. It does not affect `https://` in `SERVER_URL`.

The following complete example configures an external configuration store and a separate OpenDJ identity store. Prepare the xref:chap-prepare-install.adoc#prepare-configuration-store[configuration store] and xref:chap-prepare-install.adoc#prepare-identity-repository[identity store] first.

[source, properties]
----
SERVER_URL=https://openam.example.com:8443
DEPLOYMENT_URI=/openam
BASE_DIR=/var/lib/openam
locale=en_US
PLATFORM_LOCALE=en_US
AM_ENC_KEY=
ADMIN_PWD=REPLACE_WITH_ADMIN_SECRET
AMLDAPUSERPASSWD=REPLACE_WITH_DIFFERENT_AGENT_SECRET
COOKIE_DOMAIN=openam.example.com
ACCEPT_LICENSES=true

DATA_STORE=dirServer
DIRECTORY_SSL=SSL
DIRECTORY_SERVER=config-ds.example.com
DIRECTORY_PORT=1636
ROOT_SUFFIX=dc=am-config,dc=example,dc=com
DS_DIRMGRDN=uid=openam,ou=admins,dc=am-config,dc=example,dc=com
DS_DIRMGRPASSWD=REPLACE_WITH_CONFIG_STORE_SECRET

USERSTORE_TYPE=LDAPv3ForOpenDS
USERSTORE_SSL=SSL
USERSTORE_HOST=identity-ds.example.com
USERSTORE_PORT=1636
USERSTORE_SUFFIX=dc=example,dc=com
USERSTORE_MGRDN=uid=openam-setup,ou=admins,dc=example,dc=com
USERSTORE_PASSWD=REPLACE_WITH_IDENTITY_STORE_SECRET
----

`DIRECTORY_SSL=SSL` and `USERSTORE_SSL=SSL` select LDAPS, using the corresponding LDAPS listener ports. The installer accepts `SSL` and `SIMPLE` for these settings. Configure the server JVM to trust the LDAP certificate issuers. The configurator JVM only needs HTTPS trust for its own connection to OpenAM.

Run the configurator with the edited properties file. This example uses a certificates-only JKS trust store. Omit the trust store options if the CLI JVM already trusts the OpenAM HTTPS issuer.

[source, console, subs="attributes+"]
----
$ "$JAVA_HOME/bin/java" -Djavax.net.ssl.trustStoreType=JKS \
    -Djavax.net.ssl.trustStore=/secure/openam-https-truststore.jks \
    -jar openam-configurator-tool-{openam-version}.jar --file config.properties
----

Check the configurator output and server installation log, run the xref:chap-install-core.adoc#verify-openam-installation[readiness and sign-in checks], and remove the temporary properties file containing credentials.

The tool configures OpenAM and can provision embedded OpenDJ. Prepare external directory backends, certificates, and account permissions in advance. When adding a node to an existing deployment, use its shared configuration store and the existing deployment's settings. The separate `USERSTORE_*` settings apply to the first node. See the comments in `sampleconfiguration` for `existingserverid` and site properties, and the xref:../reference/openam-cli-tools.adoc#man-configurator-jar-1[configurator.jar reference] for invocation details.
