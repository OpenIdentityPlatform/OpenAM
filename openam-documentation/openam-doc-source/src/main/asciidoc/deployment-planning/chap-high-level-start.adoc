[#chap-high-level-start]
== Getting Started for Architects and Deployers

Use this checklist to prepare a deployment proposal, agree on acceptance criteria, and hand the service over to its operators.
For an evaluation, start with a pilot that demonstrates the critical application flows. For production, complete the acceptance and recovery checks before admitting client traffic.

[#plan-the-deployment]
=== Plan the Deployment

Assign an owner to each decision and link the corresponding evidence in the deployment plan. The roles below are examples.

[cols="2,4,4,2",options="header"]
|===
|Decision |Acceptance criteria |Evidence |Suggested owner

|[[table-openam-initial-tasks]] Scope and ownership
|Identify protected resources, client applications, environments, dependency owners, and escalation paths. Confirm which release and companion components the project will deploy.
|Service inventory, owners, and versioned bill of materials
|Deployment lead

|[[table-openam-services]] Services and integrations
|Select the authentication, federation, and authorization flows required per realm. Agree with each application and identity provider on identifiers, endpoints, credentials, certificates, and change windows.
|Integration inventory, partner approvals, and pilot test results
|Application and identity teams

|[[table-openam-deployment-objectives]] Service levels and recovery
|Set measurable availability, latency, capacity, recovery time, and recovery point objectives. Agree on which sessions and tokens may be lost during a component or site failure.
|Service-level objectives and recovery requirements per data store
|Service owner

|[[table-openam-sizing]] Capacity
|Demonstrate that peak traffic meets the objectives with a representative mix of client flows and with the planned node or site unavailable.
|Load profile, test report, and resource headroom estimates
|Performance team

|[[table-plan-the-topology]] Topology
|Identify each public and internal URL, TLS boundary, network dependency, and data store. Verify node and, where applicable, site failover and failback.
|Network and data flow diagram, data store inventory, failover test results
|Platform and directory teams

|[[table-plan-security]] Security
|Restrict administrative and internal paths, establish certificate and credential rotation, harden cookies and endpoints for the selected flows, and verify audit delivery.
|Access rules, key and secret inventory, and hardening test results
|Security and platform teams

|[[table-post-deployment]] Operational handoff
|Verify alert delivery and responsibility for follow-up. Rehearse restore, upgrade, and rollback. Agree on rollout gates and the authority to stop or roll back.
|Dashboards, alerts, recovery exercise, and operations runbook
|Operations team
|===

Use xref:chap-deployments.adoc#chap-deployments[Planning the Deployment Architecture], xref:chap-topologies.adoc#chap-topologies[Example Deployment Topology], and xref:chap-sizing.adoc#chap-sizing[Sizing Hardware and Services for Deployment] to develop and validate these decisions.

[#install-openam]
=== Install the Components

. *Choose and pin the software.* Check xref:chap-hw-sw-requirements.adoc#chap-hw-sw-requirements[Hardware and Software Requirements] and the xref:../release-notes/index.adoc[Release Notes]. Record the OpenAM release, Java runtime, servlet container, and data store versions. Record the WAR checksum or pin the container image by digest and record versions of agents, gateways, and customizations separately.
. *Prepare hosts, containers, and storage.* Use the xref:../install-guide/chap-prepare-install.adoc#chap-prepare-install[installation prerequisites] for permissions, JVM settings, and directory preparation. For the project Docker image, mount persistent writable storage at `/usr/openam/config` or at the configured OpenAM data path. In Kubernetes, assign storage to each instance that needs local persistent data. Plan stable server identities, probes, network rules, and secrets before startup. The xref:../how-to/how-to-run-openam-in-kubernetes.adoc#how-to-run-openam-in-kubernetes[Minikube tutorial] demonstrates a single evaluation instance.
. *Prepare the data stores.* Provision the configuration store, identity repositories, and CTS as called for by your topology. Verify schema, indexes, permissions, and TLS trust before configuring OpenAM. See xref:../install-guide/chap-prepare-install.adoc#chap-prepare-install[Preparing For Installation] and xref:../install-guide/chap-cts.adoc#chap-cts[Configuring the Core Token Service].
. *Configure and secure the first instance.* Use the installer or the unattended configurator for setup, and the console or `ssoadm` for administration. See xref:../install-guide/chap-install-tools.adoc#chap-install-tools[Installing OpenAM Tools]. Configure xref:../admin-guide/chap-realms.adoc#chap-realms[realms], xref:../admin-guide/chap-session-state.adoc#chap-session-state[session state], and the xref:chap-deployments.adoc#plan-security[hardening plan] before exposing endpoints.
. *Add site members and configure traffic.* Register each additional node as a distinct server in the existing deployment, with its own server URL and local configuration. Verify settings and key material that must match across site members. Configure the load balancer for the selected session model and test routing and failover. See xref:../install-guide/chap-install-core.adoc#add-servers-to-site[Add a Server to a Site] and xref:../install-guide/chap-install-multiple.adoc#configure-lb[Configuring Load Balancing].
. *Integrate and test applications.* Configure the selected xref:chap-deployments.adoc#plan-integration-with-apps[client integrations]. If the deployment uses agents or OpenIG, install the selected release on its documented platforms and verify the client and server versions together. Manage customizations as versioned inputs, and verify the full client flow against the public URL.
. *Verify and release.* Complete the xref:chap-deployments.adoc#plan-deployment-tests[deployment checks], verify xref:chap-deployments.adoc#plan-maintenance[monitoring and ownership], and rehearse xref:chap-deployments.adoc#plan-disaster-recovery[recovery]. Follow the agreed xref:chap-deployments.adoc#plan-rollout[traffic rollout and rollback plan].
. *Maintain the deployment.* Follow the xref:../upgrade-guide/index.adoc[Upgrade Guide] for planned changes to the installed release. If you decommission an instance, follow xref:../install-guide/chap-uninstall.adoc#chap-uninstall[Removing OpenAM Software] and account for its proxy routes, clients, and stored credentials.
